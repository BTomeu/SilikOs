# SilikOS: performance compared with other systems (13/11/2026)

The owner's question: "how is the performance compared to other operating systems?" Here is what has been
measured, with `tools/bench_os` (how it is done: `tools/bench_os/README.md`). No number is estimated.

## What is compared, and what is not

What is compared is **the user space and the tools each system carries**: each system runs inside its official
container image, all on **the same kernel and the same machine**. So it is **not** a comparison of kernels, of
start-up, of memory at idle, of desktop response or of graphics: none of that has been measured (see the end).

- **Machine:** x86_64, Intel Xeon at 2.30 GHz (a virtual machine in the cloud, 4 processors, 15 GB), kernel 6.18.44,
  Docker 29.9.2. The measuring container runs without network, pinned to 4 processors, writing to memory.
- **Method:** one warm-up run and then 5; the figure is the median of the wall-clock time.
- **Inputs:** generated by `tools/bench_os/gen.py`, the same on every system. The programs print a checksum and
  every system gave the same one (Icarus and Verilator also agree with each other).
- **Columns:** `almalinux-9` is SilikOS's base with CRB and EPEL. `silikos-9` is the same plus SilikOS's own builds
  (ngspice and Yosys, the RPMs of the release `eda-tools`). Everything else in `silikos-9` is **the same
  binaries** as `almalinux-9`: the difference between these two columns is the machine's noise.
- **The versions differ on each system** (GCC 11 to 16, Python 3.9 to 3.15, Yosys 0.33 to 0.70). It is what the
  user of each system gets, but a newer compiler does not do the same work as an old one.

## The noise, before reading anything

The two columns with the same binaries differ by up to 15 % (Verilator, making the model: 2.52 s and 2.90 s;
firmware: 5.51 s and 6.06 s). ngspice, measured twice, changed by up to 20 % on the same system. So:

- a difference of **less than 15 % is not a difference**;
- the rows of less than a second (link, `zstd`, decompression) give only the order of magnitude.

## Where SilikOS is slower, or behind

- **Python:** the base carries Python 3.9. The numeric loop takes 3.27 s; on Ubuntu 24.04 (3.12) 2.64 s, on
  AlmaLinux 10 (3.12) 2.90 s, on Fedora 45 (3.15) 2.96 s: between 10 % and 24 % slower. Reading the CAN log:
  2.52 s against 2.24–2.33 s (at the edge of the noise).
- **Package manager:** installing 4 tools already downloaded takes 1.13 s with dnf 4; with Fedora's dnf 5, 0.72 s.
- **`xz`, decompressing:** 0.60 s (xz 5.2.5) against 0.44 s (xz 5.6 and 5.8). A short row: order of magnitude.
- **Old versions:** GCC 11.5 native and 12.4 for ARM, where Fedora carries 16.2 and 15.2. What the generated code
  gains from that was not measured beyond this program (see the row "the compiled program": all the same).
- **ngspice and Yosys are not there** in AlmaLinux 9 or in EPEL 9 (nor in AlmaLinux 10 with EPEL 10). SilikOS
  carries them compiled; without SilikOS, the base has neither.

## What it shows

- **Yosys:** SilikOS's build (0.70) synthesises the design in 13.3 s; Fedora 45's (0.67) in 23.3 s; Ubuntu
  24.04's (0.33) in 41.0 s. It is the only large difference in the table. Why Fedora's, with a close version,
  takes 1.75 times longer was not looked into. The result is similar: 104 781, 104 891 and 107 723 cells.
- **Compiling:** the base compiles this project between 10 % and 27 % faster than the others (4.59–4.92 s
  against 5.42–5.83 s). That is because GCC 11 is older and does less work, not because the system is better.
- **The compiled code runs the same** with GCC 11, 13, 14 and 16 (5.06–5.42 s, inside the noise), in this program.
- **ngspice:** no difference that can be claimed between SilikOS's build, Ubuntu's and Fedora's.
- **Firmware, Icarus, Verilator simulating, `xz` compressing:** all inside the noise, or nearly.
- **Missing packages:** of the 9 tools tried, the base lacks 2 (ngspice, Yosys); Ubuntu 24.04 and Fedora 45,
  none. The two that are missing are the ones SilikOS adds.

In short: for compiling and simulating work, the user space of EL 9 is **neither faster nor slower** than
Ubuntu's or Fedora's in a way that shows, except for Python (slower) and Yosys (faster with SilikOS's build).

## What has not been measured

- **SilikOS's ngspice and Yosys on ARM:** the release `eda-tools` does not carry their ARM packages.
- **`xz` with 500 MB:** it took 7 minutes per run; it was measured with 64 MB.
- **Start-up, memory at idle, desktop latency, GPU, real disk, battery:** nothing. They need real hardware
  with each system installed, not containers.
- **Kernel:** EL 9's (5.14) against the others' 6.x was not compared; here all ran on 6.18.
- **Commercial tools** (Spectre, Vivado, MATLAB): none.
- **Real hardware:** all this is a shared virtual machine; the 15 % noise comes from there.
