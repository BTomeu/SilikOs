# SilikOS on EL 10: what it costs and what works today (13/11/2026)

SilikOS 9 is still the product. This is the track that keeps it from ageing: what happens to each part of SilikOS on
AlmaLinux 10.2 has been tried, in `almalinux:10` containers on the build machine (Ubuntu 24.04, kernel 6.18, 4 cores,
no KVM, network through a proxy). Everything that was done lives in `el10/`; no file of the EL 9 product has been
touched. Every statement says how it was run; what was not run is marked [A]. External facts carry their source; when
the page could not be opened from the session and only the search engine's extract is at hand, that is marked [A] too.

**The summary, in five lines:**
- EL 10.2 does not carry GNOME 47 but **GNOME Shell 49.4** (a partial rebase in 10.2), kernel 6.12, Python 3.12, glibc
  2.39, no Xorg server and no X11 session.
- Our ten RPMs build and install as they are on EL 10; the test suite passes under Python 3.12 except for two tests
  (no syntax error).
- **State on 14/11/2026:** the port of the extension follows the EL 9 extension again (the rules for the glass and for
  reading the message file, brought up to date; the glass is now clipped on 49) and there is a **lab ISO
  "SilikOS 10 lab"** that a GitHub workflow builds, installs in a virtual machine and checks: **40 checks, no
  failure** (run 43587575827). Section 9. What sections 2 to 6 say is of the version of 13/11.
- The shell extension is **ported to GNOME 49 by mechanical rules** (`el10/port_shell.py`) and has been run: the
  three looks come up in a headless GNOME Shell 49.4, Start opens, the COMMAND bar works as a Wayland client.
  Left: the glass, the shell theme and everything that needs a screen and hands.
- Of the 24 tool recipes, 21 resolve their build dependencies; four have been built and tried.
- PROPOSAL: SilikOS 10 as a parallel track from now, and a product when Synopsys and Cadence list RHEL 10 for the
  releases the owner uses; hardware alone does not justify it yet (section 8).

**x86-64-v3.** RHEL 10 is built only for x86-64-v3. AlmaLinux 10 follows that in the `x86_64` architecture and
also publishes a separate architecture `x86_64_v2` (ISO, repositories and an EPEL rebuilt by AlmaLinux, `.alma_altarch`
packages), "ONLY for older hardware". What it means for SilikOS:
- AlmaLinux's notes: "All 3rd party packages for RHEL10 will target x86-64-v3". The vendors' tools and Fedora's EPEL
  are v3: the v2 variant is of no use for an EDA workstation.
- Measured: a program built with `rpmbuild` on EL 10.2 carries the note `x86 ISA needed: x86-64-baseline, x86-64-v2,
  x86-64-v3` (`el10/results/builds.txt`): our tool RPMs for EL 10 will not start on a CPU without AVX2.
- The owner's Ryzen 7 5800HS is v3 [A: by the model; not run there]. The build machine is v4 (`ld.so --help`).
- AlmaLinux's NVIDIA driver does not exist for `x86_64_v2`.

**EPEL 10.** It has a tree for each minor of the base (`pub/epel/10.2/`); `el10/repos.sh` picks the system's. There is

## 4. The shell extension on GNOME 49

40. 49 does not load it: since 45 extensions are ES modules and `metadata.json` has to say the version.

`el10/port_shell.py` (`python3 el10/port_shell.py --rules` lists them with the number of places). GNOME's porting guides
(gjs.guide) were read in a copy of their source on GitHub (gjs.guide was not reachable); "src" means read in the

## 7. How to run it again

```
el10/box.sh -- bash el10/check_set.sh            # the package set (EL 10); -i 9 for EL 9
el10/run_tests.sh 10                             # the tests under Python 3.12
el10/box.sh -- bash el10/build_tools.sh resolve  # BuildRequires of each recipe
el10/build_tools.sh build stm32flash dfu-util netgen
python3 el10/port_shell.py                       # makes the port of the extension again
el10/shell_image.sh                              # the image with GNOME Shell 49 (once)
SILIK_SHELL_RUN=1 el10/shell_check.sh            # syntax + the three looks in a headless shell
el10/box.sh -i silikos-el10-shell -- bash el10/install_try.sh
el10/xwayland_try.sh host
```

To start the shell in the container it took: a user that is not root, an empty system bus, and removing the folder
`/run/systemd/seats` that the image carries (with it the shell asks for systemd's login manager, which is not there,
and stops; without it, it takes its replacement). No GPU, seat or systemd is needed. (13/11: there was no GitHub workflow for this; since 14/11 the `shell` job of `.github/workflows/el10.yml` does it: section 9.)

## 8. Recommendation (PROPOSAL)

**When SilikOS 10 has to exist.** Three things decide it, in order:

1. **The vendors.** SilikOS exists so that Virtuoso and Sentaurus run on it. Today [A]: Cadence puts RHEL 10 on the
   roadmap of the 2026.x releases; from Synopsys no mention of RHEL 10 was found up to Y-2026.09; from MathWorks, none
   either. A base that the second vendor does not support cannot be the product.
2. **The hardware.** The argument "new laptops need a new kernel" is weaker than `docs/STRATEGY.md` assumed:
   EL 9.8's kernel 5.14 carries, backported, the modules of the 2024-2026 platforms that were looked for in
   BaseOS's file lists: `xe` (Intel Lunar/Panther Lake graphics), `ath12k` and `mt7925e`
   (Wi-Fi 7), `snd-sof-pci-intel-mtl/lnl/ptl` (Meteor/Lunar/Panther Lake audio), `intel_vpu`, `amd-pmf`. Of those looked
   at, only `rtw89_8922ae` (Realtek's Wi-Fi 7) and `intel-ipu6` (MIPI cameras) are in EL 10.2 and not in EL 9.8. That
   the module is there does not mean the laptop works: only `silik hw report` on a machine says that. Mesa is
   25.2.7 on both. Snapdragon X: no statement of support found for either.
3. **EL 9's clock.** Full support until 31/05/2027 [A]: until then EL 9 still gets new hardware. After that
   only security until 2032, and GNOME 40 and GTK 3 no longer move.

**Proposal:**
- **Now:** keep this track alive at little cost: `el10/port_shell.py` at each change of the extension (the test warns),
  `el10/check_set.sh` at each minor of EL 10. Write no new code that is only good for GNOME 40.
- **First half of 2027:** a "lab SilikOS 10": the EL 10 ISO with the ported extension, for the open tools, the bench
  and the hardware that EL 9 does not carry; without promising the vendor tools on it. These are the 23–33 days [A]
  of section 4.
- **Product:** when Synopsys and Cadence list RHEL 10 (or Alma/Rocky 10) for the releases the owner has
  licensed and one of them has been run on SilikOS 10 [A: 2027-2028, by Synopsys's 36-month cycle].
- **Meanwhile, on SilikOS 9:** none of this touches it. The old tools will stay in the EL 6/7/8 boxes on
  SilikOS 10 too; what changes is that the session will be Wayland and X11 will go through Xwayland.

**Mind the moving base:** Red Hat has changed GNOME 47 for 49 within the life of EL 10 (10.0 → 10.2). A shell
extension on EL 10 has to be tried again at each minor; on EL 9, GNOME 40 has never moved. It is a new maintenance
cost, and one more reason for the port to be a script and not a copy.

## 9. The lab ISO "SilikOS 10 lab" (14/11/2026)

the EL 9 one (`tools/build_iso.sh`, which has not been touched). It is a lab system, not the product: there is no
Wine, none of the tools we build, no shell theme, and no vendor tool tried.
